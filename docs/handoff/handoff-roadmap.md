## 2. 一期产品目标与临床底线

### 2.1 核心流程

医护施测人员在临床工作端创建或选择患者与访视
→ 完成最低充分的设备准备检查和不计分操作练习，由医护确认患者理解操作方式
→ 发起受监督患者施测
→ 患者施测终端按步骤合同呈现并语音播报当前题目内容和施测指导语，按需提供版本化受控测量刺激
→ 患者施测终端与临床工作端协同完成 MMSE / MoCA：点击、书写和绘图等数字交互由患者完成，闭眼、拿纸、对折、放置等动作观察、实物操作和专业判断由医护记录、纠正和确认
→ 系统对适用语音回答步骤支持必要的录音和转写，同时支持计时及患者点击、书写与绘图采集
→ 医护施测人员及时查看步骤、状态、进度、患者求助和异常，并在必要时暂停、接管、纠正、恢复或终止
→ 完成结果送入医生异常优先复核；医生能够展开必要事实、记录修订原因并显式整体确认
→ 医生确认后的结果受控形成或更新正式 ItemResponse
→ 提交、评分、报告
→ PDF / 打印 / 受控下载
→ 必要时更正或逻辑作废
→ 数据及按数据保留合同纳入备份的媒体可恢复和追溯。

### 2.2 逻辑工作区与临床职责

一期按职责划分三个核心逻辑工作区，不要求建设三套独立应用：

1. **患者施测终端**：面向患者完成听题、阅读、点击、语音回答、书写和绘图；只呈现当前施测所需的最少信息，不显示分数、报告、答案、诊断倾向、医生意见或其他患者信息。
2. **临床工作端**：在同一前端应用和工作流内区分医护施测模式与医生复核报告模式。医护施测模式负责准备、发起、监管、动作观察、异常和影响因素记录、暂停、接管与恢复；医生复核报告模式负责复核语音、转写、书写、绘图、观察记录、评分和报告。医生可以同时承担两种职责，不强制两个账号、两个互斥角色或两套应用。
3. **临床运营与系统管理工作区**：承担最低充分的账号运营、患者与访视维护、临床任务入口、异常会话、报告输出和作废；允许复用既有页面或受控工具，不建设统计型 Dashboard 或复杂管理平台。

- 医护施测人员可以是医生，也可以是经过授权和训练的其他医护人员；医生负责最终复核、整体确认和报告。现有 `nurse`、`doctor` 或其他固定角色如何承载具体职责，由 WP-10.0 / WP-12 锁定，不在本 roadmap 新增角色枚举或权限设计器。
- 知情者辅助信息由临床工作端或临床运营工作区承载，不作为第四套完整应用，也不与患者施测终端混用。

### 2.3 产品、呈现与设备边界

- 医护人员必须在场或进行监督；一期不开放无人监督的居家 MMSE / MoCA 核心施测。
- 标准患者交互设备包括平板，以及具备触摸功能的电脑大屏，例如触控一体机或连接触控显示器的电脑。标准设备应具备或能够接入满足施测要求的触控、音频播放、麦克风和受支持浏览器环境；扬声器和麦克风可使用合格外设。摄像头不是标准 MMSE / MoCA 患者交互设备的通用前置，当前不因跨设备进入、动作观察或媒体能力而默认要求摄像头；未来若某个已锁定施测步骤确需拍摄、扫码或其他摄像头能力，由该步骤合同单独锁定业务必要性、权限、隐私、设备适配和验收范围。手机只承担经过逐步骤适配和验收的有限兼容交互，不替代标准设备的完整 MMSE / MoCA 流程验收；普通非触控电脑主要用于临床工作端的监管、复核和报告操作，普通鼠标操作不等同患者触控设备验收。现有医生侧图片上传和纸笔结果拍照等媒体能力不因此删除或取消。
- 完整 MMSE / MoCA 由患者施测终端与临床工作端协同完成，不要求所有题目由患者脱离医护自行完成；阅读闭眼、三步实物指令、动作观察及其他专业判断不得机械改写为患者独立点击题。
- 患者短期受控施测会话和安全进入是一期必要能力。同一设备从医护工作模式交接到患者施测模式时不强制二维码、短码或第二设备配对；只有临床工作端与患者施测终端位于不同设备时，才需要短期配对、医护确认或其他安全进入机制。具体交接、配对和会话失效合同由 WP-10.0 确定，不预设二维码为唯一方案。
- 医护施测人员可及时查看当前施测状态，并在必要时暂停、接管、纠正和恢复患者操作；控制权切换后，旧患者写入不得覆盖医护形成的新事实，网络中断后按服务端权威状态恢复。具体同步时效、刷新策略和传输技术由 WP-10.0 按最低充分方案确定，不预设屏幕镜像、毫秒级双端同步、实时监听、多患者监管大屏、双端协同编辑或特定事件平台。
- 患者施测终端应根据施测步骤语音播报当前题目内容和施测指导语。每个步骤由后续合同分别锁定题目或指导文字是否显示、是否播报、自动播放或患者主动播放、是否允许重播及次数或条件、播放完成前能否作答，以及播放中断或失败的处置；不得以全局规则统一所有步骤。
- 题目内容、施测指导语、影响测量条件的刺激、普通操作和状态提示必须分层。普通题目与指导可采用经确认的录音或运行时 TTS；词语、数字串、复述句、警觉性刺激等继续使用版本化、可复现且播放受控的音频。是否显示文字服从题目规则，视觉任务只播报必要指导且不得增加答案提示；不把页面全部文本交给全局 TTS，也不在本 roadmap 选择 TTS 厂商、音色或具体 API。
- 测量刺激的节奏和重播策略由施测步骤合同确定。开始、等待、音量、上传、请求医护协助等普通操作和状态提示可使用经确认的录音、运行时 TTS、文字或提示音，不要求全部录制并绑定固定音频版本。
- 正式施测前提供最低充分的准备流程：提示标准触控设备和浏览器可用性，确认屏幕方向和有效交互区域，完成音量试听，并在适用语音步骤需要时完成麦克风试听，提供触摸或书写试操作，确认当前施测语言，记录视力、听力、语言或手部活动等明显影响因素，并至少完成一个不使用正式测量刺激的不计分练习。医护确认患者理解后才开始正式施测；练习不进入 ItemResponse、评分或报告，不改变正式计时和重播事实，也不扩展为训练平台或通用教程系统。
- 患者施测终端采用一步一屏、单一主要操作、大字号、大触控区、足够间距和明确求助入口；规则未明确允许时患者不得自行跳题。播放、录音、上传、等待医护和完成等状态必须清楚，不以复杂导航、密集表单、游戏化积分、诊断暗示或自动快速切题增加负担。
- 同设备交接进入患者模式后，患者不能借助后退、刷新、历史记录或普通导航进入临床工作端。患者模式只显示当前施测所需的最少身份信息；完成、终止或超时后清除当前患者可见内容，结束页只提示已完成并要求交还设备。返回临床工作端必须由医护显式安全解锁或重新验证，具体采用重新登录、快速验证或其他方式由 WP-10.0 锁定。
- 一期只对量表步骤合同明确需要语音回答的步骤支持录音和一种可用的基础 ASR，并由医生复核；动作观察、选择、点击、书写和绘图等非语音步骤不因患者施测端存在而默认录音。ASR 失败时允许医生听取已有录音、重新发起转写或直接人工录入，ASR 服务不可用不得阻断整个施测。不建设多供应商动态路由、流式字幕、方言自动识别、自动语义评分或实时答案生成，也不在 roadmap 选择厂商或具体 API。
- ASR 只提供辅助转写。自动转写、医生修订和医生确认后的最终答案必须可区分；只有医生确认结果才是正式临床事实。
- 系统不自动形成最终医学诊断，量表结果不能脱离临床访谈和其他检查使用。
- 一期临床试用闭环不等于医疗器械注册完成，也不等于法定数字签名、CA / PKI 或电子印章能力完成。
- 患者施测终端只服务院内受监督 MMSE / MoCA 闭环，不扩大为家庭照护门户或通用量表流程设计器。
- HIS / EMR、计费、保险及其他第三方医院系统集成不属于当前一期、WP-09 或上线验收门禁，也不作为本 roadmap 的二期候选。

### 2.4 不可削弱的临床安全底线

- 医护身份、固定角色权限和患者数据隔离。
- 医生最终复核；ASR、自动评分或系统规则均不替代医生确认。
- 医生复核遵循异常优先和最低操作负担：适用语音步骤、书写绘图、医护观察、暂停 / 接管 / 重做 / 异常中断、缺失不一致、低可信、人工评分、影响因素及无法完成原因必须重点复核；合同明确、无异常且无歧义的简单客观步骤可以汇总呈现和受控批量确认，但最终提交前仍须医生显式整体确认。
- 自动转写、医生修订与最终确认结果可区分；适用语音回答步骤的原始录音或等价证据在医生复核和必要追溯期间可用。
- 医护接管的控制权与并发保护，避免患者施测终端与临床工作端同时形成相互覆盖的正式写入。
- 患者点击、书写和绘图等数字交互证据，与医护动作观察和实物操作结果记录保持可区分，并足以支持医生复核、错误恢复和必要追溯；动作观察不默认视频录制、摄像头、传感器、姿态识别、计算机视觉或行为分析。图片、适用步骤录音及其他必要媒体遵循同一最低充分原则；绘图不默认保存完整压力、速度、停顿、事件历史或回放数据，也不自动分析或评分。
- 患者施测、医护接管、转写修订、医生确认、报告输出和作废等关键操作留痕。
- 共享设备上的患者可见信息最小化；患者模式结束后不能查看分数、报告、医生意见、其他患者信息或返回临床工作端。
- 知情者辅助信息必须标明信息来源并与患者作答、MMSE / MoCA ItemResponse 和正式量表得分分离，不自动改分或形成诊断、报告结论。
- 报告版本保留、逻辑作废、作废标识和历史可追溯，不以物理删除替代。
- 数据库以及数据保留合同要求纳入正式备份的媒体可备份并验证恢复；不默认全部原始录音、中间媒体、失败草稿或全部绘图事件永久保存并进入长期备份。
- MMSE / MoCA 主链必须经过自动化、真实设备和人工签收；桌面 Browser 不替代真实设备或专业判断。
- 系统不自动形成最终医学诊断。

- 患者施测终端与医护施测模式的步骤分工，以及状态查看、控制权、接管和服务端权威恢复。
- 测量刺激、普通指导、适用语音回答步骤的录音、基础 ASR 与人工降级边界。
- 患者点击、书写和绘图证据，以及医护动作观察和实物操作结果记录的复核边界。
- 共享设备患者模式、患者可见信息、结束清除和医护安全解锁边界。
- 影响因素与无法完成原因的结构化分类、异常优先复核、汇总确认和医生最终整体确认边界。
- 原始录音复核期与保留期、全量或选择性长期保留、哪些中间结果可删除、绘图保存最终图 / 基础轨迹 / 其他必要元数据的范围、正式备份媒体范围，以及删除、恢复和访问责任。
- 医生复核确认后受控形成或更新正式 ItemResponse 的边界。
- 安全、并发、网络恢复与关键留痕。
- 标准触控设备、手机有限兼容、自动化与真实设备边界。

WP-10.0 尚未开始，本 roadmap 不预先锁死具体 Schema 或集合数量、WebSocket / SSE / 轮询方案、ASR / TTS 厂商、语音音色、endpoint、DTO、错误码、角色枚举、患者 UI 页面结构细节，也不预分配 WP-10 内部全部长期子阶段编号。详细产品与数据合同由后续 WP-10.0 任务形成。

### 4.2 WP-10：受监督患者施测底座与 MMSE 闭环

**目标**

- 患者短期受控施测会话与安全进入；同设备交接不强制配对，跨设备时采用短期配对、医护确认或其他安全机制。
- 患者施测终端采用一步一屏、单一主操作、大字号、大触控区、明确状态和随时可达的求助入口，并适配平板和具备触摸功能的电脑大屏等标准触控设备；手机只承担逐步骤验收后的有限兼容。
- 按施测步骤播报当前题目内容和指导语，逐步确定文字显示、语音、自动 / 手动播放、重播和作答门禁；测量刺激版本化、可复现并受控播放，普通指导可采用录音、运行时 TTS、文字或提示音，不使用全页面无差别 TTS。
- 正式施测前完成设备 / 浏览器提示、方向和交互区域确认、音量及适用时的麦克风试听、触摸或书写试操作、语言确认、明显影响因素记录和至少一个不使用正式刺激的不计分练习；练习不进入 ItemResponse、评分、报告或正式计时 / 重播事实。
- 同设备患者模式隔离临床工作端及无关患者信息，完成、终止或超时后清除患者可见内容并安全交还；返回临床工作端需要医护显式解锁或重新验证。
- 对适用的语音回答步骤支持录音和一种基础 ASR，并提供医生人工降级、自动计时和受控重播策略；非语音步骤不默认录音。
- 采集患者点击、书写和绘图等数字交互，并由医护记录和确认闭眼、拿纸、对折、放置等动作观察与实物操作结果；不默认视频、摄像头、传感器或自动动作识别。
- 医护施测模式支持选择患者 / 访视 / 量表、确认准备、发起交接或跨设备进入、查看进度和求助、记录动作观察及结构化影响因素，并可暂停、接管、恢复、纠正或终止；分类至少覆盖感官、手部操作、语言 / 文化 / 教育、指令理解、疲劳 / 情绪 / 拒绝、环境、设备 / 网络和其他临床原因，但具体枚举由 WP-10.0 锁定，记录不自动改分或诊断。
- 医生复核报告模式按异常优先呈现适用语音、转写修订、书写绘图、医护观察、异常步骤、人工评分、影响因素和无法完成原因；无异常且无歧义的客观步骤可汇总呈现和受控批量确认，不机械要求逐题点击。医生修改须有原因和留痕，最终仍须显式整体确认。
- 医生确认后的结果受控形成或更新正式 ItemResponse，并接入既有提交、评分和报告链。
- 完整 MMSE 患者施测闭环。

**完成定义**

- 医护人员在场或监督条件下，患者施测终端与临床工作端协同完成完整 MMSE；适合数字交互的步骤由患者通过标准触控设备完成，动作观察、实物操作和专业判断由医护记录和确认。
- 医护人员始终拥有暂停、接管、纠正和恢复权，患者端中断后可按服务端权威状态安全恢复；患者完成后共享设备安全退出患者模式。
- 正式施测前准备和不计分练习完成，练习事实不进入正式作答、评分、报告或正式计时 / 重播记录。
- 正式结果只由医生确认后进入既有提交、评分和报告链；系统不自动诊断。

### 4.3 WP-11：MoCA 多模态患者施测闭环

**目标**

- 完成交替连线、立方体、钟表、图片命名、两轮记忆、数字广度、警觉性、词语流畅性、抽象和延迟回忆提示树。
- 逐步骤锁定题目文字、指导语语音、视觉刺激、自动 / 手动播放和重播组合；数字串、记忆词和警觉性刺激保持版本化、受控节奏，条件提示明确播放与显示边界。
- 在平板、触控一体机和连接触控显示器的电脑上提供经步骤合同确认的有效绘图区域；手机仍仅承担适用步骤的有限兼容。
- 支持固定节奏刺激、条件步骤、复杂绘图，以及医生复核、错误恢复和数据保留合同要求范围内的必要证据。

**完成定义**

- 完整 MoCA 由患者施测终端与临床工作端协同完成，并在医生复核报告模式形成闭环；不要求全部步骤由患者独立操作。
- 正式评分仍只基于医生确认后的 ItemResponse，不由 ASR、患者原始作答或必要过程事实直接形成。

### 4.4 WP-12：临床运营最小闭环

**目标**

- 最小账号运营能力：医护账号开通、启停、密码重置和固定角色分配；可按最低充分合同采用简单管理员页面、受控运维工具、管理脚本或页面与工具组合，不预设完整用户管理 UI。
- 患者和访视编辑、更正与归档。
- 最小临床入口能力：患者查找或创建、访视建立、发起施测，以及查看进行中、待复核、待报告和异常任务；允许复用既有患者列表、访视详情、筛选和聚合入口，不预设新建完整首页或 Dashboard。
- 明确临床工作端与临床运营及系统管理工作区的职责边界；允许复用同一前端应用、既有页面和受控工具，不强制拆分应用或建设新的统计首页。
- 最小知情者辅助信息采集：由医护在患者或访视上下文中代为结构化记录，明确来源为知情者，并记录其与患者关系、接触频率或了解程度等必要背景；医生在报告确认前可查看。具体采用的经授权问卷或字段由后续产品合同单独确定。
- 知情者信息与患者作答、MMSE / MoCA ItemResponse 和正式量表得分分离，不自动改分，不自动形成诊断或报告结论。
- 正式 PDF、打印、受控下载和版本标识。
- 报告逻辑作废、作废标识、版本保留。
- 患者施测、医护接管、转写修订、医生确认、报告输出和作废等关键留痕。

**完成定义**

- 首批临床用户可通过最低充分的账号运营和临床入口完成账号、患者、访视、施测任务、报告输出和错误处置。
- 医护能够代录最小知情者辅助信息，医生能够在报告确认前查看；一期不要求知情者长期账号、独立入口、家庭照护门户、家属聊天、随访提醒、报告共享、多知情者协作或短期自助链接。
- 知情者短期受控链接仅可作为 WP-12 后续条件扩展；只有量表授权、身份与隐私边界、失效规则和真实临床需求明确后才重新评估，本次不锁定。
- 不包含自定义权限设计器、患者自动合并、复杂物理删除、统计型 Dashboard、电子签名平台或独立审计中心。

### 4.5 WP-08：临床端到端联调与真实设备验收

**目标**

- 患者施测终端、临床工作端、临床运营与系统管理工作区、评分、报告和错误处置完整联调。
- 验收平板、具备触摸功能的电脑大屏（触控一体机或连接触控显示器的电脑）、代表性手机有限兼容，以及音频播放、麦克风、触控、绘图、网络中断、医护接管、老年用户可读性和医护操作负荷；合格外设可以提供音频和麦克风能力。摄像头不作为标准设备固定验收项；未来只有已锁定施测步骤确有业务必要时，才按该步骤合同单独验收其权限、隐私和设备适配。普通非触控电脑验证医护监管、医生复核和报告操作，但鼠标结果不替代患者触控设备验收。
- 验收同设备患者模式交接、医护电脑与患者平板的跨设备流程、医护电脑与触摸电脑大屏的跨设备流程、逐步骤题目与指导语播报、准备检查、不计分练习、患者求助、暂停 / 接管 / 恢复、共享设备隐私退出、医护施测到医生异常优先复核和报告，以及医护代录知情者辅助信息。

**完成定义**

- MMSE / MoCA 完整临床主链通过自动化、真实设备和人工签收。
- Batch E 当前 8 项保留历史 ID 和 `pending` 状态，主要归属仍为 WP-08。WP-08 启动时必须基于 WP-10、WP-11、WP-12 最终合同、标准设备和真实流程重新执行阶段 A/B/C：仍适用项目保留原 ID；被新流程替代、与新增候选重复或已不可达的项目可标记 `superseded` 或 `retired`，但必须记录原因和替代证据；必要的新患者语音、触摸电脑大屏、跨设备安全进入、医护接管和患者可读性候选按最终合同纳入。
- WP-08 的完成标准是最终适用的自动化、真实设备和人工候选全部关闭，不等同于机械关闭当前历史 8 项。
- 不得用桌面 Browser 结果替代真实设备或专业判断。

### 4.6 WP-09：部署、备份、监控与试用上线

**目标**

- 受控生产部署。
- 建立与受控临床试用风险相匹配的最小运行监控、备份告警、故障恢复和回滚能力。
- 数据库及数据保留合同要求纳入正式备份的媒体可验证恢复。
- Secret 管理；进程和依赖存活、数据库连接、媒体存储可用性、备份成功 / 失败、基础错误率和容量风险的最低充分监控与告警。
- 运维责任和院方试用签收。
- 不建设全链路 tracing 平台、复杂指标大盘、日志搜索集群、自研告警中心或业务智能监控系统。

**完成定义**

- 部署与回滚演练完成。
- 数据和合同要求纳入备份的媒体可验证恢复。
- 生产配置与最小运行保障门禁通过，并完成受控临床试用上线。

| 居家随访与家庭照护协同 | 明确可脱离医护监督的任务、患者身份核验、隐私、可访问性、异常升级和照护责任；核心 MMSE / MoCA 不作为无人监督居家自测 |

“居家随访与家庭照护协同”不包含一期的院内受监督患者施测端。测量刺激音频，以及适用语音回答步骤的录音和基础 ASR 已进入一期受监督患者施测范围，不属于本表延后项。

## 8. 文档维护规则

1. roadmap 是一期目标、范围、工作包、依赖和当前主线的唯一事实源。
2. Git commits 回答按时间顺序发生了什么；旧工作包历史通过本文件处置记录和 Git 历史追溯，不静默删除。
3. backend / frontend snapshot 只回答当前代码真实实现了什么和仍未实现什么，不复制未来工作包表。
4. API / DTO / Service / Route / Component map 回答实现在哪里、当前契约是什么；decisions 回答为什么这样设计。
5. testing playbook 回答如何验证、实际验证到了什么程度；不得自行启动或关闭 roadmap 工作包。
6. roadmap 不维护 commit 文件清单、完整 API / Schema 明细、测试数量流水或尚未锁定的技术方案。
7. 一期范围变化时必须记录新增、延期、缩减、替代、取消或规模调整及原因，且不得重复计算。
8. 候选二期能力不得写成合同承诺、当前实现或一期隐含前置。
