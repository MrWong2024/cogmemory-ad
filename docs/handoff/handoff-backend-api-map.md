# CogMemory AD / 智忆评 后端 API 地图

## 1. 文档定位

本文档是当前公开 Backend HTTP API 的 endpoint map，唯一完整维护 endpoint 名称、HTTP method/path、Controller、Guard/Roles、请求 DTO 名称、响应 type 名称、HTTP status、endpoint-specific 读写职责、高层副作用/幂等/状态转换、主要业务错误与公开安全/隐私边界。

- 请求/响应字段、validation、transform、whitelist、nested shape 与 field-level safe exposure：见 [Backend DTO Cheatsheet](./handoff-backend-dto-cheatsheet.md)。
- Service 内部算法、CAS/屏障实现、一致性与恢复顺序：见 [Backend Service Map](./handoff-backend-service-map.md) 和 current code。
- 受监督患者施测的 same/cross、逐题、媒体、ASR、technical replay、takeover/redo 与 F2/F3 稳定合同：见 [Patient Administration Contract](./handoff-patient-administration-contract.md)。
- 测试与 evidence：见 [Backend Testing Playbook](./handoff-backend-testing-playbook.md)；工作包状态：见 [Roadmap](./handoff-roadmap.md)。

本文档不展开 DTO 字段、完整 response shape、Service 调用/重试算法、前端消费流程或测试结果。非 owner 中删除的重复副本由上述 authoritative owner 保留，不属于信息丢失。

## 2. 当前公开 surface 与共同约定

- current source inventory：17 个 Controller 文件、65 个公开 endpoint；Auth、Patients/Visits、Scales、Assessment Execution、Media、Submission、Scoring、Cognitive Domains、Reports/History 与 Patient Administration 均有公开 API。
- 当前没有公开用户管理、注册、密码重置、短信验证码、OAuth/SSO、JWT 登录、患者通用编辑/归档/合并、评分重跑/锁定、认知域人工修改/确认、报告签名/PDF/AI 等 API。
- Controller、DTO 与 response type 的 current 事实以 current code 为准；本表的 65 个 endpoint 均与 Controller inventory 对齐。
- `PW` 表示类级 `SessionAuthGuard + RolesGuard` 与 `admin | doctor | nurse | research_assistant`；`D/A` 表示方法级收窄为 `doctor | admin`。
- 除表中公开/患者会话例外外，`PW` endpoint 的共同 HTTP 边界为 DTO/path validation `400`、未认证 `401`、角色不足 `403`。这些共同状态不在每行重复。
- 所有 DTO 字段只在 DTO Cheatsheet 完整维护；表中只列 DTO/type 名称。无独立响应 type 的极简响应或二进制流允许内联。

### 3.1 System 与 Auth（4）

| Endpoint | Controller | Auth | Request DTO | Response / status | Endpoint 职责、错误与安全边界 |
|---|---|---|---|---|---|

## 4. Endpoint-level ownership boundaries

- DTO 字段、nested `structured_manual` / `binaryManualDecision` / timing / evidence upload shape 与完整 public response 字段：只在 DTO Cheatsheet 维护。
- A14 revision CAS、父级启动、A16 submission barrier、A15 Storage/绑定补偿、report freeze/correction recovery、ASR claim/finalize：只在 Backend Service Map/current code 维护。
- Patient Administration 的逐 step、same/cross、technical replay、takeover、redo、ASR/adoption 业务合同：只在 Patient Contract 维护。
- 前端 credentials/cache/cancellation/retry/error kind 与 response 消费：只在 Frontend API Map 维护。
- 测试/evidence 与工作包状态分别由 Testing Playbooks 与 Roadmap 维护。
