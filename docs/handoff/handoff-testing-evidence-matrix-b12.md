## 1. 口径

- `建议主证据层` 每行恰有一个值，只使用 `backend_unit`、`backend_http_e2e`、`backend_public_mapper`、`frontend_pure_or_synthetic`、`browser_business_route`、`browser_cross_cutting`、`profile_database_verifier`、`static_gate`、`manual_or_device`。
- `sufficient` 只表示仓库内已经存在能在成功执行时直接证明该稳定要求的可执行断言；它不表示该 ID 已执行、已通过或已关闭。`partial` 表示只有部分事实或只有测试基础设施；`missing` 表示直接证据为 `gap`；`conflicting` 表示现有直接断言彼此冲突。
- `historical_observation` 只记录历史运行观察，充分性一律不得高于 `partial`。fixture E2E、synthetic infrastructure、Browser test list、post-browser verify、代码静态阅读和本矩阵本身均不单独关闭 B12。
- `是否必须 Browser=yes` 表示该 ID 的用户可见渲染、交互或真实 BrowserContext 事实不可下沉；`cross_cutting_only` 表示主业务事实可由非 Browser 层证明，但仍需在代表 route 上验证共享 Browser 边界；`no` 表示该稳定要求本身不依赖 Browser。
- `最小 fixture / 前置状态` 是证据所需的最小合法状态，不改变当前 fixture contract。`横切检查组=none` 表示该行只承担业务断言；横切组只抽样共享实现，不能抽样业务语义。

## 7. 当前 22 条 core route 的重复成本

`frontend/test/browser-acceptance/b12/b12-core-support.ts` 的 `B12BrowserSession.collect()` 当前对每个 Session/route 统一执行以下横切收口：三个 Web Storage 为空、document.cookie 边界、URL query/hash、全 DOM privacy、Console warning/page error、真实 logout 与 Cookie 清除、CORS、五阶段 auth ledger、全部非本 route Action 请求为 0。22 条 core route 中，多 Context route 还会按 Session 重复这些检查。

主要无意义重复与建议归属：

- 完整 auth lifecycle、logout Cookie 与 CORS：移至 `auth-route-deidentified` 代表 route；其他业务 route 只需要已认证前置和自有 Context 精确关闭。
- Storage/URL 全审计：移至持有真实 dirty draft 并执行刷新/导航的 `storage-refresh`；只读/空表单 route 不重复。
- generic Console/Network 零噪声：成功基线放 `doctor-lock-success`；409、403、401、abort route 只保留自己的错误码、次数、initiator、failure 与恢复断言。
- 全 DOM 敏感值扫描：放信息量最高的 `doctor-lock-success`；audit-unavailable、metadata-unsupported、non-diagnostic-language 仍执行各自专属禁止值断言。
- 七类非 owner Action：static gate 为主，`unsupported-actions` 为代表 Browser 辅助；其他 route 只检查自己的预期写请求数。
- viewport/Axe/focus/ARIA：只在 `responsive-accessibility` 完整执行；业务 route 仍保留其特有 label、checkbox、disabled 和 error 文案。

仍须逐业务场景保留的断言包括：doctor 与 admin 入口/首锁差异；nurse、research_assistant 与 system 的不同访问语义；首次锁定与 alreadyLocked；两类 conflict；401 与 403；网络中止与业务错误；draft、pending、confirmed、locked；audit unavailable 与 metadata unsupported；所有本地 note/checkbox/stale/continue/refresh 行为；各 route 的精确预期写入与数据库后置合同。

公共 support 失败的影响应被限制在其横切 owner ID。当前 `collect()` 将所有横切断言耦合进每条 route，因此 B12-B2 的 logout 后 `/auth/me` 分区错误、B12-B4 的 auth slice/共同 locator、B12-B6 的 navigation auth 计数都曾使已完成业务步骤的 route 统一失败并使 62 个 ID 归零。G2 应明确拆分“业务断言结果”和“横切代表结果”，但不得在 G1 修改 support、owner、route 或历史状态。

## 9. 证据失效与 G2 审核输入

逐行失效条件已覆盖以下变化源：A22 DTO/endpoint、lock service 状态机、ReportsService 原子 filter/`$set`、public mapper/response、LockPanel/Hook、角色权限、Session/auth shell、fixture/Stage/verifier、产品 route、样式/响应式/label、Playwright support。失效是“该行需重新建立对应层证据”，不是所有 88 项无差别重跑。

G2 重点争议项：

1. B12-31 是否以现有 Playwright synthetic 对纯 request builder 为主、真实 POST Body 只做代表连接检查；不得假设新增前端 runner。
